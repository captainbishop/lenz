Safe fixture checks from the repository root after the documented dependencies are installed:

~~~sh
node --test integrations/intent-testnet/swap.test.mjs web/intent-near-relay.test.mjs web/intent-aurora-swap.test.mjs web/intent-lending-read.test.mjs web/intent-zcash-relay.test.mjs
~~~

This fixture command passed 71 tests on November 17 in the inspected checkout. It does not submit a transaction. Live checks require their documented owner, funded assets, native wallet or sponsor configuration and explicit financial authorization.

The source links show implementation ownership. The original NEAR verifier is upstream code; Lenz adds the mounted request, signature, relay, journal and outcome path. Aurora's adapter is an explicit funded fixed-rate test venue. Zcash's native SDK and keys remain separate from browser storage and backups.

For direct Bluetooth messages, [Chat](../../web/public/chat.js) selects [delivery mode](../../web/public/delivery-mode.js) and the [native client](../../web/public/bluetooth-client.js). Bluetooth, Nostr, carrier and WebRTC clients use the same [saved-packet eligibility policy](../../web/public/delivery-packets.js). The [origin-bound Android host](../../native/android/src/app/lenz/nearby/MainActivity.java) carries encrypted envelopes through [GATT and retry handling](../../native/android/src/app/lenz/nearby/BluetoothMesh.java). [Authenticated saved intake and receipt preparation](../../web/public/receive-packet.js) run inside each caller's state update; the [signed receipt protocol](../../web/public/delivery-receipts.js) establishes message arrival separately from link acknowledgements and financial settlement. The [physical observation](android-ble-20261117.json) covers direct messages on two Android phones; JVM/native doubles cover deterministic retry and fragmentation cases.
