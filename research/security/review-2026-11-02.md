removes the unused Intents SDK tree (zero remaining helper-tree advisories),

relay cancellation race. It also found a missing dependency installation-policy
file. These fixes are local. No commit, push, deployment, funding or live financial
transaction was performed as part of this review. The baseline is
`3b683eea721b8e3f899b9f41c74eb417d5aef322`, plus the local executor and fixes described
below. This is an internal review, not an independent security certification.

## Solidity review and preparation

Twelve specialty passes covered arithmetic, authority, economic effects, execution
flow, invariants, external boundaries and combinations of those concerns. No
complete exploit with an identifiable victim was reproduced in these two local
contracts. This result does not extend to the rest of Lenz or establish proof
soundness. Two investigation leads remain:

| Location | Observation | What remains unproved |
| --- | --- | --- |
| `PlonkVerifier.verifyProof`, including nested `checkProofData` | Commitment coordinates are bounded by scalar modulus `q`, although curve membership uses the larger base modulus `qf`. A valid curve point in that excluded interval was constructed. | No complete valid proof using such a point, practical rejected user operation or material harm was demonstrated. |
| `PlonkVerifier.verifyProof` | Public inputs enter the transcript as raw words and field arithmetic reduces them; there is no explicit public-input `< q` check at this entry. All seven unchanged-proof `public[i] + q` attempts failed. | No accepted noncanonical proof or current settlement consumer exploiting one was demonstrated. |

The saved Slither reports parse with `success=true` and no reported analyzer
error. The verifier report contains 120 entries: 14 `incorrect-return`, 22
`assembly`, one `dead-code`, 79 `naming-convention`, one `solc-version` and three
`unused-state`. The 14 high-labelled candidates point to intentional failure
paths that write zero and return the verifier's false Boolean. They do not
demonstrate proof acceptance or a payout. The other entries are maintenance and
analysis observations. The original command, process exit code and source binding
were not recovered, so this is review of saved output, not a newly executed scan.
Slither 0.11.6 and Foundry binaries were confirmed in a separate tools directory;
neither resolves on the default PATH. No callable analyzer MCP or inspected
Aderyn/Mythril installation was found. Installation is not scan coverage.

The preparation checklist scores **69.1/100: needs work** after the scope-document
fix. This is a weighted checklist result, not a security probability or measured
test coverage. Inapplicable financial controls receive no deduction.

  approved network access. The two NEAR scan failures are advisory results, not
  installation failures, and are retained above.

## Release and integration limits

The executor remains a developer component. Wallet consent and atomic reservation,
nearby executor handoff, integration of the recipient-side chain verifier, live
executor tests and independent operators are required before product activation.
An encrypted observation or storage receipt cannot credit wallet funds. Private-only
policy must continue to reject the transparent NEAR route.

Safe recovery of copied devices and outstanding obligations, independent release
and signing authority, missing-callback/liability coverage, a funded Aurora route,
Intents execution/refunds, Zcash product signing and the full private settlement
relation remain open. The test-only proof setup cannot protect real funds.
Windows/browser fixtures do not close physical-device validation.

Security review must accompany design, implementation and publication, as set out
in the [security policy](../../SECURITY.md). Resolve the dependency and coverage
gaps with component-specific evidence before treating this as a release-readiness
decision. This report records completed checks and unresolved work; it does not
approve publication or real-fund use.
